# LatticeGuard

> 🇷🇺 Русский | [🇺🇸 English](README.md)

Pet-проект на основе прорыва **OpenAI Astra #7**: *polynomial-factor hardness of approximation for the Closest Vector Problem (CVP)*.

Этот проект демонстрирует, как новые математические результаты могли бы повлиять на практические дискуссии о постквантовой криптографии на решётках (LWE / Kyber / Dilithium).

> ⚠️ **Статус исследования:** Этот проект — **образовательная эксплорация**, а не криптографический стандарт. Показанные сокращения параметров — **иллюстративные оценки** на основе упрощённой модели. Они **не являются валидными параметрами ML-KEM** и не должны использоваться в продакшене. Статус Astra #7: «Lean 4-сертификаты опубликованы, но рецензирование продолжается.»

## Что нового (улучшенная версия)

Этот релиз добавляет несколько улучшений качества жизни, сохраняя весь оригинальный функционал:

- **`.gitignore`** — предотвращает случайный коммит `__pycache__`, виртуальных окружений и файлов результатов.
- **`requirements.txt`** — зафиксированная версия NumPy, совместимая с Termux.
- **`test_lattice.py`** — 13 юнит-тестов, работающих без pytest (чистый Python).
- **`export.py`** — экспорт результатов демо/бенчмарка в JSON или CSV (полезно для анализа на десктопе).
- **`--json` флаг** — `demo.py` и `benchmark.py` поддерживают машиночитаемый JSON-вывод.
- **`--export` флаг** — сохранение результатов бенчмарка напрямую в файл.
- **Улучшенный `setup.sh`** — проверяет версию Python, верифицирует NumPy и выдаёт понятные ошибки.
- **Валидация входных данных** — `lattice.py` теперь проверяет параметры и корректно обрабатывает вырожденные базисы.
- **Стандартное отклонение** — бенчмарк теперь выводит `std_ms` для каждой размерности.
- **Статистика по многим seed** — демо CVP теперь прогоняется на множестве seed для демонстрации вариативности.
- **Нативное C-расширение** — опциональный `gs_native.c` с Python-биндингами через `ctypes` для сравнения производительности.

## Редукция решёток: LLL

Проект включает чисто-Python реализацию алгоритма **LLL (Lenstra-Lenstra-Lovász)** редукции решёток. Это демонстрирует ключевую концепцию криптографии на решётках: «хороший» базис делает решётку совершенно другой по сравнению с «плохим», но он **не** ломает правильно сконструированную LWE.

### Что делает LLL

LLL преобразует случайный базис в эквивалентный, который:
- **Почти ортогонален** — векторы близки к 90° друг к другу
- **Относительно короток** — длины векторов ограничены фактором от кратчайших возможных

### Демо: случайный vs LLL базис

```bash
python demo.py
```

Пример вывода (n=16):
```
--- Демо: влияние LLL-редукции на Babai rounding ---
Параметры: n=16, q=97, seed=42

Средняя длина вектора базиса:
  Random: 219.0
  LLL:    98.9
  Улучшение: 2.2×

Babai rounding — совпадений с секретом:
  Random basis: 0/16 (0%)
  LLL basis:    0/16 (0%)

=> LLL делает базис в ~2 раза короче,
=> но Babai rounding всё равно не восстанавливает секрет.
=> Этот toy-эксперимент не моделирует полный спектр решётчатых атак на LWE, которые могут использовать приближённую редукцию, перебор, сито, декодирование или primal/dual стратегии. LLL сама по себе не даёт оценки concrete security для LWE.
```

### Интерпретация

| Тип базиса | Средняя длина вектора | Babai match rate | Вывод |
|-----------|----------------------|------------------|-------|
| Случайный | ~219 | ~0% | Плохой базис, эвристика не справляется |
| LLL-редуцированный | ~99 | ~0% | Хороший базис, эвристика **всё равно** не справляется |

Это ключевой аргумент безопасности LWE: даже с высококачественным базисом задача **Closest Vector Problem** остаётся сложной, потому что вектор ошибки `e` тщательно подобран так, чтобы целевая точка `b` находилась далеко от любого вектора решётки. LLL помогает с *аппроксимацией* CVP, но LWE спроектирована так, чтобы сопротивляться именно этому.

### Где это применяется в реальной криптографии

В криптографии на решётках:
- Публичный LWE-инстанс можно вложить в базис решётки, непригодный для известных атак.
- Это не следует интерпретировать буквально: секретный ключ — это не обязательно короткий или редуцированный базис. Точная связь между публичными параметрами и секретным ключом зависит от конкретной схемы и формулировки атаки.
- ML-KEM (Kyber) использует Module-LWE, а не простую trapdoor lattice scheme в смысле GPV/Falcon.
- LLL сама по себе не ломает правильно параметризованную LWE.

## Нативное C-расширение (опционально)

Для образовательного сравнения производительности Python и нативного C на Gram-Schmidt:

```bash
# Компиляция
bash native/build.sh

# Тест
python gs_native.py
```

Нативное расширение реализует **только ортогонализацию Грама-Шмидта**.
Babai rounding остаётся на Python (достаточно быстро — ~0.7 мс).

Оно **не обязательно** для основного демо. Проект отлично работает на чистом Python/NumPy.
Расширение существует для демонстрации FFI и измерения оверхеда Python на тight loops.
**Измеренный прирост на Android 12 (aarch64):**

| n | Python (мс) | Нативный C (мс) | Ускорение |
|---|-------------|-----------------|-----------|
| 8 | 0,57 | 0,22 | **2,6×** |
| 16 | 1,85 | 0,11 | **17,5×** |
| 32 | 7,15 | 0,18 | **39,7×** |
| 64 | 28,87 | 0,45 | **64,8×** |

Прирост растёт с n, потому что Python-реализация использует вложенные циклы, а C-версия устраняет оверхед интерпретатора.

**Численная эквивалентность:** `max_abs_error(Python, C) = 8,44e-14` — все проверенные размерности совпадают с машинной точностью.

> **Примечание:** Эти цифры измеряют только явные циклы Грама–Шмидта. Основной `benchmark.py` измеряет полный NumPy-роутин (включая `np.linalg.solve` для Бабаи), поэтому его время отличается. Нативное расширение меняет только производительность; оно не меняет криптографическую модель или вероятность успеха атаки.

## Зачем это нужно обычному человеку?

### Бытовая аналогия
Представь, что твой банк использует математическую задачу с сотнями координат в многомерном пространстве. Чтобы украсть твой ключ, вору нужно решить чрезвычайно сложную геометрическую задачу. Но квантовый компьютер делает это в тысячи раз быстрее. Поэтому банки переходят на **постквантовую криптографию** — задачи становятся ещё больше, и телефону приходится их постоянно обрабатывать.

**Если Astra #7 подтвердится и окажется применимым:** это может стимулировать дискуссии о более эффективных задачах с сохранением той же защиты. Телефон мог бы работать быстрее, приложения — меньше тормозить, а батарея — садиться медленнее. Но это пока исследовательское направление, а не развёрнутое решение.

### Где это применяется
- **Банковские приложения** (Сбер, Т-Банк, Revolut) — защита транзакций от квантовых атак.
- **Мессенджеры** (Signal, WhatsApp) — шифрование сообщений с постквантовой стойкостью.
- **VPN и Tor** — защита трафика от будущих квантовых снифферов.
- **IoT и умный дом** — датчики и камеры с ограниченной памятью получают криптографию без перегрузки.

### Что показывает это демо
1. **Эвристика Бабаи не работает даже в игрушечном масштабе** — при n=24 она восстанавливает 4% секрета на этом инстансе. При криптографических размерностях toy-эксперимент не оценивает стоимость атаки.
2. **Математика напрямую влияет на твой телефон** — новая теорема, если подтвердится, может вдохновить на создание меньших ключей и более быстрых приложений.
3. **Проверь сам** — весь код открыт, запускается на телефоне за 0.5 секунды, никакой «магии».

## Воспроизводимость

- **Параметры безопасности и оценки BKZ** — полностью детерминированы (формулы из упрощённой модели).
- **Демо-атака (Babai rounding)** — использует фиксированный `seed=42`, поэтому результат (1/24, 4%) воспроизводим. Если убрать seed, результат будет варьироваться в диапазоне 0–15% совпадений — это нормально и демонстрирует случайность базиса.
- **Статистика по многим seed** — прогон на 100 seed показывает, что эвристика систематически не справляется на случайных инстансах.
- **Время выполнения** — зависит от устройства, на современных флагманах < 0.3 сек, на бюджетных — до 2 сек.

## Статус подтверждения Astra #7

**Lean 4-сертификаты опубликованы, но рецензирование математическим сообществом продолжается.**

OpenAI опубликовала все 10 доказательств с машинно-проверяемыми Lean 4 сертификатами и пошаговыми рассуждениями модели. Это исключает самый распространённый провал AI-генерации доказательств — правдоподобные, но содержащие скрытую ошибку цепочки рассуждений. Однако машинная проверка Lean — это не то же самое, что рецензирование математическим сообществом: учёные должны подтвердить, что формализованное утверждение соответствует исходной гипотезе, и что человеческое «направление» модели не исказило результат.

Ключевые факты:
- **Lean 4 формализация:** каждое доказательство имеет машинно-проверяемый сертификат в [GitHub-репозитории](https://github.com/openai/ten-proofs).
- **Внешняя верификация:** математик Томас Блум (ранее ловивший ошибки OpenAI) и лауреат Филдсовской премии Тимоти Гауэрс участвовали в верификации предыдущих результатов Astra.
- **Ещё не окончательно:** внешние математики ещё не успели детально разобрать все десять аргументов. Опровержение любого из результатов было бы громким событием.
- **Прецедент First Proof:** в феврале 2026 OpenAI представила 10 доказательств на вызов *First Proof*; 5 признаны «вероятно корректными», 1 позже опровергнут, остальные — на рецензировании.

**Вывод:** Lean-сертификаты делают эти результаты *значительно более достоверными*, чем типичные AI-анонсы в математике, но окончательный вердикт математического сообщества ещё не вынесен. Это демо рассматривает Astra #7 как *правдоподобное направление* для оптимизации параметров, а не как установленный факт.

## Решение проблем

### `ImportError: No module named numpy`
Запустите `bash setup.sh` или `pip install numpy`.

### `ldd: error: expected absolute path`
Это особенность Termux, не связанная с проектом. Используйте `readelf -d ./file | grep NEEDED`.

### Тесты падают при первом запуске
Убедитесь, что вы в директории проекта и `lattice.py` импортируется:
```bash
cd ~/lattice-guard
python test_lattice.py
```

### Бенчмарк медленный на старом устройстве
Это ожидаемо. Попробуйте меньшие размерности:
```bash
python benchmark.py --n 8 12 16 24
```

### Нативное расширение не компилируется
Убедитесь, что установлен C-компилятор:
```bash
pkg install clang
bash native/build.sh
```
Если компиляция не удалась, проект работает без него — просто проигнорируйте предупреждение.

## Теория

- **LWE (Learning With Errors):** основа постквантовой криптографии (Kyber, Dilithium).
- **CVP (Closest Vector Problem):** нахождение ближайшего вектора решётки к заданной точке.
- **Astra #7:** доказана полиномиальная трудность аппроксимации CVP — то есть даже приближённое решение остаётся вычислительно сложным (если доказательство выдержит проверку).
- **Babai rounding:** простейшая эвристика для CVP. На случайном базисе практически бесполезна — что и показывает демо.
